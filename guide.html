CHAMPION — Launch Guide

Developer brief · User manual · Admin manual · Deployment (GitHub + Vercel + custom domain) — Tampa, FL · Sept 2–5, 2026

1 · What CHAMPION is

CHAMPION is a live scoreboard for the conference's six competitions. It has two screens built from the same data:

  • The app (phones) — dashboard with the featured "Up Next" matches, all three tournament brackets (FC World Cup, College Football Playoff, Call of Duty), all leaderboard competitions (Benchpress, Crucible, John Wick Challenge, plus any you add), and a Latest Results feed. Attendees browse; admins update everything from the same screen after unlocking with the PIN.
  • The big screen (TVs / projector) — read-only landscape display of all brackets, all leaderboards, and the Latest feed. Refreshes every 3 seconds. Each bracket auto-anchors to its highest played phase, and roughly every 2 minutes the brackets take turns slowly panning through all their rounds.

Current state: both screens are finished designs that run in a browser and store data on the device (localStorage). To launch for real — many phones, one shared scoreboard — a developer wires the data layer to a small server, described in §4–5. Everything else ships as-is.

2 · User manual (attendees)

  • Home — "Up Next" cards show the next (or admin-featured ★) match in each tournament. Below: all six competitions with their current status or leader, then Latest Results across everything. Tap anything to jump to it.
  • Brackets tab — pick a tournament to see the full two-sided bracket with the Final in the center. Use − / + to zoom, Reset to restore, and rotate the phone for the widest view. Winners are marked W; FC World Cup and CFP matches also show scores. A red-bordered match is still to be played; the champion banner appears when the Final is decided.
  • Compete tab — leaderboard competitions. Each shows its top 5 (leader highlighted), the scoring type (fastest time, heaviest weight, or highest count), and an Updates feed of posts and automatic results.
  • No account, no install required. For one-tap access, use the phone's Add to Home Screen from the share menu — it then opens full-screen like an app.

3 · Admin manual

Tap Admin (top right) and enter the PIN — Champs26, case-sensitive, 8 characters. Change it before the event (§5, step 4). The button turns red while admin mode is on; tap it again to turn it off.

Brackets

  • Record a result — tap the winner's name in any ready match. A confirm popup appears; for FC World Cup and CFP you can optionally enter both scores there. Confirming advances the winner to the next round. Tapping a different name later re-routes the bracket (downstream results are cleared, with confirmation).
  • Change a matchup — drag any competitor's name onto another slot (works with touch). A Confirm Changes popup summarizes the swap before it applies. Only unplayed matches can be changed.
  • Feature a match — tap ☆ on a ready match to pin it as that tournament's "Up Next" on everyone's Home screen; tap ★ to unpin.
  • Set up a bracket — in the panel below the bracket, enter one competitor per line, choose Random draw or List order seeding, then Generate bracket. This resets that tournament's results. Byes are placed automatically when the count isn't a power of two.

Leaderboard competitions

  • Add a result — on a competition page, enter name + score (+ body weight for Benchpress) and tap +. Times are entered as m:ss. Entering an existing name updates that person's score instead of duplicating them.
  • Automatic updates — the app posts to the feed on any top-5 change: new leader / fastest time, extending the lead, entering the top 5, moving up a spot, or improving while holding rank. These appear in the competition's Updates, the Home feed, and the big screen.
  • Manual updates — post free-text announcements from the same page (schedules, calls to the stage, records).
  • Add a competition — on the Compete tab: name it and pick a scoring type — Timed (m:ss, fastest wins), Weight (LBS, highest wins), or Count (reps/points, most wins). It appears everywhere immediately, including its own big-screen panel ("Awaiting results" until the first entry). Remove a competition with ✕ (confirmed, irreversible).

Big screen

  • Open the big-screen URL in a browser on the TV / projector computer, press F11 for full screen. It is read-only and needs no PIN.
  • It updates itself every 3 seconds. The bracket panning sequence runs automatically; no operator needed.

4 · Developer brief

Front end. Two self-contained HTML pages (app + big screen), no framework build required. All state lives in one JSON document, currently persisted under the localStorage key champion-app-v2. The big screen reads the same key and polls it every 3 s — which is why, today, both pages must run on the same device. Deployment replaces localStorage with a tiny API.

Data model (one JSON document)
{
  tournaments: [{ id, name, seeding: 'order'|'random', scored: bool,
    entrants: [names], featured: {r, i} | null,
    rounds: [ [ { a, b, winner, bye, ts, sa, sb } ] ]   // rounds[0] = first round
  }],
  competitions: [{ id, name, unit: 'TIME'|'LBS'|'REPS', lowerBetter: bool,
    hasBW: bool, board: [{ name, bw?, score }],
    updates: [{ ts, text, auto? }]
  }]
}

Server work (the only real engineering):

  1. GET /api/state — returns the JSON document. Called on load and polled (app 5 s, big screen 3 s).
  2. POST /api/state — body { pin, data }. Verify pin against the ADMIN_PIN environment variable server-side, then write the document. Reject otherwise. The client-side PIN gate stays as UX only — never as security.
  3. Storage: Vercel KV (Redis, one GET/SET key) is the simplest fit for a single small JSON document; Vercel Blob also works. Traffic is one document, a few hundred readers, ~1 write per result — free tier is plenty.
  4. In the pages, replace the loadData()/save() localStorage calls with fetch to those two routes, and send the entered PIN with each write. Last-write-wins is acceptable with one or two admins; if several admins work at once, add a version number to the document and reject stale writes.

Suggested repo layout (Next.js is the path of least resistance on Vercel): public/ or app routes serving the two pages + assets (banner, RMI logo), and app/api/state/route.js with the two handlers. Total server code is well under 100 lines.

5 · Deployment — GitHub → Vercel → your domain

  1. GitHub. Create a private repo (e.g. rmi/champion), commit the project. Every push to main will auto-deploy; branches get preview URLs for testing.
  2. Vercel. Sign in with GitHub at vercel.com → Add New Project → import the repo. Vercel detects the framework and deploys; you get champion-xxx.vercel.app immediately.
  3. Storage. In the Vercel project: Storage → Create → KV, connect it to the project. The connection env vars are injected automatically.
  4. PIN. Settings → Environment Variables: add ADMIN_PIN with a fresh value (retire Champs26 once it has been shared in documents like this one). Redeploy to apply.
  5. Custom domain. Settings → Domains → add e.g. champion.yourdomain.com. At your DNS registrar add the record Vercel shows: for a subdomain, CNAME champion → cname.vercel-dns.com; for an apex domain, A @ → 76.76.21.21. HTTPS certificates are issued automatically within minutes.
  6. Routes. Serve the app at / and the big screen at /big-screen on the same domain.
  7. Distribute. Generate a QR code pointing at the domain, print it on signage and programs. TVs open /big-screen full-screen.
